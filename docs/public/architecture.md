# 架构与数据处理

Electron Main负责文件授权、会话目录、后端生命周期、最终保存和系统接口。React Renderer负责输入、预览与状态；preload仅暴露固定桥接方法。Python后端负责PDF解析、文字/图像识别、实际内容移除和导出。

用户输入每行一项要打码的文字，默认直接导出PDF，也可先预览并按文字查看实际位置。识别疑问集中展示，未找到文字时明确保留原文的副本含义。编辑输入后旧结果失效，相同有效结果可以重复保存或导出图片。

后端输出先保存关闭，再重新打开核对结构、页数、几何和实际打码位置报告。输出以可见静态页面构建，移除元数据、附件、书签及可交互载体，表单/批注转为不可编辑内容。默认另存副本。结构检查不代替最终内容核验或人工判断。

Renderer不能提供任意输出路径；Main只接受用户选择的精确文件与单次保存目标。异步任务绑定输入与结果身份，迟到响应不覆盖当前任务。最终复制期间等待实际文件I/O完成，退出时收束写入、自有后端与私有会话；不按未经验证的旧PID终止进程。

PDF.js及其worker、字体、CMaps和解码资源本地打包；预览读取通过Main的精确文件授权，禁止任意目录访问。系统安全存储不可用时不静默将OCR凭证明文保存。诊断日志避免记录业务正文和凭证。

本地 OCR 在本机处理。无位图的文字页如含被识别为可能构成轮廓文字的图形，会在本机补识别并标记该页供核对。文字转成图形后可能漏检或识别错误。请在共享前对照原件检查这类文字，即使该页未出现补识别提示。

选择 PaddleOCR 或百度 OCR 会将文档或页面发送至所配置服务，使用前请确认数据可提交。轮廓文字的补识别沿用本地 OCR。云接口要求 HTTPS，Paddle 地址与返回链接有独立请求边界。请勿将 API 密钥写入代码、问题反馈或版本库。
